# 环境配置说明

## 📁 文件结构（业界标准）

```
SE-Project/
├── deploy/
│   ├── .env                    # 🔴 实际配置（不提交 Git）
│   └── .env.example            # ✅ 配置模板（提交 Git）
│
└── PolyMetric/frontend/
    ├── .env.development        # ✅ 开发环境默认值（提交 Git）
    └── .env.production         # ✅ 生产环境默认值（提交 Git）
```

## 🎯 各文件用途

### 1. `deploy/.env` - Docker 部署配置
**用途**: Docker Compose 自动读取此文件  
**包含**: 数据库密码、Redis密码、服务器IP等  
**安全**: ⚠️ 包含敏感信息，不要提交到 Git

### 2. `deploy/.env.example` - 配置模板
**用途**: 新环境初始化时复制此文件  
**命令**: `cp deploy/.env.example deploy/.env`  
**安全**: ✅ 不包含真实密码，可以提交

### 3. `PolyMetric/frontend/.env.production` - 前端生产环境
**用途**: 
- Vite 构建时的默认 API 地址
- Docker 构建时会被 `ARG VITE_API_BASE_URL` 覆盖

**当前值**: `http://127.0.0.1:8080`（本地部署）

### 4. `PolyMetric/frontend/.env.development` - 前端开发环境  
**用途**: 本地 `npm run dev` 时使用  
**当前值**: `http://127.0.0.1:8000`（直连Django）

## 🔄 环境切换

### 方法1: 使用切换脚本（推荐）

```bash
cd deploy/scripts
./switch-env.sh
```

**选项**:
- `1` - 本地开发 (127.0.0.1)
- `2` - 测试服务器 (49.232.40.152)
- `3` - 生产服务器 (124.220.26.26)
- `4` - 自定义 IP
- `5` - 从模板重置

### 方法2: 手动修改

编辑 `deploy/.env`，修改一行：

```bash
SERVER_IP=你的服务器IP
```

其他配置会自动适配（通过变量替换）：
```bash
ALLOWED_HOSTS=localhost,127.0.0.1,${SERVER_IP}
CORS_ALLOWED_ORIGINS=http://localhost,http://${SERVER_IP}
```

## 🚀 部署流程

### 本地部署
```bash
# 1. 配置环境变量
cd deploy/scripts
./switch-env.sh  # 选择 1 (本地开发)

# 2. 启动服务
cd ../docker
sudo docker-compose build
sudo docker-compose up -d
```

### 服务器部署
```bash
# 1. 配置环境变量
cd deploy/scripts
./switch-env.sh  # 选择 2 或 3 (服务器)

# 2. 上传代码到服务器
rsync -avz --exclude-from=.gitignore \
  ./ user@server:/path/to/project/

# 3. 在服务器上启动
ssh user@server
cd /path/to/project/deploy/docker
docker-compose build
docker-compose up -d
```

## ⚡ 为什么前端构建慢？

### 原因
1. **首次构建**: 需要下载 Node 镜像、安装依赖
2. **`npm install`**: 安装几百个包需要时间
3. **Vite 构建**: 编译和打包 Vue 代码

### 优化建议（已实施）

✅ **多阶段构建**: 最终镜像只包含编译后的静态文件  
✅ **分层缓存**: package.json 未变时复用 npm install 缓存  
✅ **Alpine镜像**: 使用轻量级基础镜像

### 加速技巧

**使用国内镜像源**（可选）:

编辑 `PolyMetric/frontend/.npmrc`:
```
registry=https://registry.npmmirror.com
```

**后续构建会快很多**:
- 首次构建: ~2-5分钟
- 代码修改后: ~30秒-1分钟（利用缓存）
- 只修改配置: 几秒钟

## 🔍 常见问题

### Q: 为什么注册时提示网络错误？
A: 前端使用了错误的 API 地址。已通过以下方式修复:
1. 删除冲突的 `frontend/.env` 文件
2. 更新 `.env.production` 为正确端口 8080
3. 重新构建前端镜像

### Q: 如何验证配置是否生效？
```bash
# 检查前端使用的API地址
sudo docker exec polymetric-frontend sh -c \
  "grep -o 'http://127.0.0.1:[0-9]*' /usr/share/nginx/html/assets/*.js | head -1"

# 应该输出: http://127.0.0.1:8080
```

### Q: 多人协作时如何管理配置？
1. 每个人复制 `.env.example` 创建自己的 `.env`
2. `.env` 不提交到 Git（已在 .gitignore）
3. 需要新配置项时，更新 `.env.example` 并提交

## 📝 配置检查清单

部署前确认：
- [ ] `deploy/.env` 存在且配置正确
- [ ] `SERVER_IP` 设置为目标环境
- [ ] 数据库和 Redis 密码已修改
- [ ] SECRET_KEY 已更换（生产环境必须）
- [ ] 端口未被占用 (80, 8080, 8443)
- [ ] Docker 服务正在运行

## 🎓 业界最佳实践

✅ **DO**:
- 使用 `.env.example` 作为模板
- 敏感配置不提交到版本控制
- 不同环境使用不同配置文件
- 自动化配置切换流程

❌ **DON'T**:
- 不要在代码中硬编码配置
- 不要提交包含密码的 `.env`
- 不要在多个地方重复配置
- 不要忘记更新生产环境密钥
