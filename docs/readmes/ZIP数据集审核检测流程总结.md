# ZIP数据集审核检测流程总结

## 核心流程概述

用户上传ZIP数据集后，系统会经过以下两个主要阶段的审核和检测：

1. **ZIP文件解析与验证阶段** - 解压ZIP文件，验证JSON数据和图片文件
2. **数据验证与AI能力分析阶段** - 验证数据格式并使用大模型判断能力维度

## 关键时间节点

| 阶段 | 执行时间 | 执行方式 | 状态变化 |
|------|----------|----------|----------|
| 文件上传 | 即时 | 同步 | `is_verified=false`, `capability_tag=processing` |
| ZIP解析 | 即时 | 同步 | 解压并验证ZIP结构 |
| 格式验证 | 即时 | 同步 | 验证通过/失败 |
| 能力分析 | 异步 | Celery后台任务 | `capability_tag` 更新为具体能力类型 |
| 验证结果处理 | 自动 | 系统自动 | `is_verified=true/false` |

## ZIP特有的处理流程

### 1. 文件结构识别
系统按以下优先级处理ZIP文件：
1. 优先查找 `data.json` 作为数据文件
2. 如果不存在，查找第一个JSON文件
3. 扫描所有图片文件（支持多种格式）

### 2. 数据格式支持
ZIP数据集支持多种JSON结构：
- **直接数组格式**：`[{"input": "...", "answer": "..."}, ...]`
- **对象包含数据数组**：`{"data": [...], "total": 100}`
- **测评类型特定结构**：`{"subjective": [...]}`, `{"objective": [...]}`, `{"adversarial": [...]}`

### 3. 图片处理机制
- **图片统计**：自动统计ZIP中包含的图片数量
- **路径验证**：验证JSON中引用的图片路径是否存在
- **访问接口**：提供专门的API访问ZIP中的图片文件

## 状态字段说明

### is_verified（审核状态）
- `false`：数据集正在审核中，等待管理员审核
- `true`：数据集已通过管理员审核

### capability_tag（能力分析状态）
- `processing`：正在分析能力维度
- `no_file`：文件缺失，无法进行能力分析
- `no_samples`：无有效样本，无法进行能力分析
- `analysis_failed`：分析失败，请检查数据集格式或稍后重试
- `language`：自然语言理解能力
- `reasoning`：数学推理能力
- `coding`：代码能力
- `other`：默认状态，无法分类的数据集

### ZIP特有字段
- `has_images`：是否包含图片文件
- `image_count`：图片文件数量

## 验证规则

### 主观测评 (subjective)
- 必需字段：`input`, `reference`
- 图像数据集额外需要：`image` 字段（图片文件路径）
- 字段类型：非空字符串
- 验证内容：每行数据必须包含这些字段的非空值

### 客观测评 (objective)
- 必需字段：`input`, `answer`
- 图像数据集额外需要：`image` 字段（图片文件路径）
- `input` 要求：包含至少两个选项（如 A. B. C.）
- `answer` 要求：单个选项字母（如 A/B/C）
- 验证内容：答案必须在题目选项中

### 对抗测评 (adversarial)
- 必需字段：`input`
- 图像数据集额外需要：`image` 字段（图片文件路径）
- 字段类型：非空字符串
- 验证内容：每行数据必须包含input字段的非空值

## 图片访问机制

### 访问接口
- **单个图片**：`GET /api/datasets/{id}/image/?filename=xxx.jpg`
- **图片列表**：`GET /api/datasets/{id}/images/`

### 支持的图片格式
- JPEG (.jpg, .jpeg)
- PNG (.png)
- GIF (.gif)
- BMP (.bmp)
- WebP (.webp)
- SVG (.svg)

### 图片路径要求
- 必须使用相对于ZIP根目录的相对路径
- 路径区分大小写
- 支持子目录结构

## 前端集成要点

1. **上传后立即轮询**：每2秒查询一次状态
2. **状态UI展示**：根据不同状态显示相应提示
3. **图片预览**：使用专门的图片访问接口
4. **错误处理**：提供清晰的错误信息和处理建议
5. **轮询限制**：最多轮询30次（约1分钟）

## 常见问题与解决方案

### Q1: ZIP上传后提示"未找到JSON文件"
**原因**：ZIP文件中没有包含JSON文件
**解决**：确保ZIP中包含至少一个JSON文件，优先使用`data.json`

### Q2: 图片无法访问
**原因**：JSON中的图片路径与实际文件不匹配
**解决**：检查JSON中的图片路径是否正确，确保使用相对路径

### Q3: 上传后提示"JSON格式错误"
**原因**：ZIP中的JSON文件格式不正确
**解决**：使用JSON验证工具检查文件格式，确保语法正确

### Q4: 能力分析失败
**原因**：数据样本不足或AI模型调用失败
**解决**：确保JSON中包含足够的数据样本，检查网络连接

### Q5: 图片文件过大
**原因**：ZIP中包含过大的图片文件
**解决**：压缩图片文件，单个图片建议不超过10MB

## API接口速查

### 上传ZIP数据集
```
POST /api/datasets/
Content-Type: multipart/form-data

name: 数据集名称
description: 数据集描述
category: 数据集类别 (text/image/multimodal)
evaluation_type: 测评类型 (subjective/objective/adversarial)
file_format: zip
file_path: [上传的ZIP文件]
is_public: true/false
```

### 查询状态
```
GET /api/datasets/{id}/capability_status/
```

### 访问图片
```
GET /api/datasets/{id}/image/?filename=xxx.jpg
GET /api/datasets/{id}/images/
```

### 管理员审核
```
POST /api/datasets/{id}/verify/
```

## 性能考虑

1. **文件大小限制**：100MB
2. **抽样数量**：能力分析只取前5条数据，提高处理速度
3. **图片处理**：按需提取，不预先解压所有图片
4. **异步处理**：能力分析使用异步任务，不阻塞用户操作
5. **缓存机制**：图片访问使用适当的缓存策略

## 安全机制

1. **权限控制**：只有管理员可以审核数据集
2. **隐私保护**：未审核通过的数据集只有创建者可见
3. **错误隔离**：详细的错误信息只记录在日志中，用户看到简化的提示
4. **路径验证**：严格验证图片路径，防止目录遍历攻击
5. **文件类型检查**：只允许访问图片文件，防止其他文件泄露

## 最佳实践

### 1. ZIP文件准备
- 使用标准ZIP格式，避免密码保护
- 优先使用 `data.json` 作为数据文件名
- 使用相对路径引用图片
- 保持合理的文件结构

### 2. 图片文件管理
- 使用常见的图片格式（JPEG、PNG）
- 控制单个图片文件大小
- 使用有意义的文件名
- 合理组织图片目录结构

### 3. JSON数据结构
- 根据测评类型包含必要字段
- 确保图片路径与实际文件匹配
- 保持数据结构的一致性
- 添加ID字段便于管理

### 4. 上传过程
- 选择正确的测评类型
- 确保文件大小不超过限制
- 上传后耐心等待处理完成
- 验证图片是否能正常访问

### 5. 错误处理
- 仔细阅读错误提示信息
- 根据错误类型采取相应措施
- 必要时联系技术支持

## 与其他格式的主要区别

| 特性 | ZIP数据集 | JSON数据集 | CSV数据集 |
|------|-----------|------------|------------|
| 文件结构 | 复杂（JSON+图片） | 简单（单一JSON） | 简单（单一CSV） |
| 图片支持 | 原生支持 | 不支持 | 不支持 |
| 数据格式 | 灵活（多种结构） | 标准（数组格式） | 标准（表格格式） |
| 处理复杂度 | 高（解压+验证） | 低（直接解析） | 中（编码转换） |
| 适用场景 | 多模态数据、图像数据 | 结构化数据 | 表格数据、已有CSV |
| 访问方式 | 专门API访问图片 | 直接JSON访问 | 转换后JSON访问 |
| 文件大小 | 通常较大 | 通常较小 | 通常中等 |
