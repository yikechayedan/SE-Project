# 数据集审核检测流程说明（更新版）

## 概述

当用户上传数据集后，系统会经过一系列自动化审核和检测流程，以确保数据集的质量和适用性。整个流程包括格式验证和能力分析两个主要阶段，不再需要人工审核。

## 详细流程

### 1. 数据上传阶段

#### 1.1 文件上传
- 用户通过 `POST /api/datasets/` 接口上传数据集
- 系统检查文件基本属性：
  - 文件大小不超过100MB
  - 文件格式为支持的类型（CSV、JSON、ZIP）

#### 1.2 初始验证
- **文件格式验证**：检查文件是否可以正确解析
- **基本结构验证**：确保文件不为空且结构正确

#### 1.3 测评类型特定验证
系统根据用户选择的测评类型（subjective/objective/adversarial）进行特定验证：

**主观测评 (subjective)**：
- 每个条目必须包含 `input` 和 `reference` 字段
- `input` 和 `reference` 必须是非空字符串

**客观测评 (objective)**：
- 每个条目必须包含 `input` 和 `answer` 字段
- `input` 中必须包含至少两个选项（如 A. B. C.）
- `answer` 必须是单个选项字母（如 A/B/C）

**对抗测评 (adversarial)**：
- 每个条目必须包含 `input` 字段
- `input` 必须是非空字符串

### 2. 数据集创建与状态初始化

#### 2.1 数据集记录创建
- 验证通过后，系统创建数据集记录
- 设置初始状态：
  ```python
  is_verified = False  # 未通过验证
  capability_tag = "processing"  # 正在处理
  capability_dimension = "other"  # 默认能力维度
  ```

#### 2.2 文件信息统计
- 计算文件大小（MB）
- 统计样本数量
- 检查是否包含图片（如果是ZIP文件）

### 3. 异步能力分析

#### 3.1 触发异步任务
- 数据集创建成功后，系统自动触发 `analyze_dataset_capability` 异步任务
- 该任务使用Celery在后台执行，不阻塞用户操作

#### 3.2 能力维度分析过程
1. **数据抽样**：从数据集中抽取前5条样本
2. **AI判断**：调用大模型分析样本，判断数据集的能力维度：
   - `language`：自然语言理解、生成、翻译等
   - `reasoning`：数学推理、逻辑推理等
   - `coding`：代码生成、代码理解等

#### 3.3 验证结果处理
- **格式验证通过 + 能力分析成功**：设置 `is_verified=true`
- **任一环节失败**：设置 `is_verified=false`，记录错误原因

#### 3.4 能力分析状态更新
分析结果可能的状态：
- `processing`：正在分析中
- `no_file`：文件缺失，无法进行能力分析
- `no_samples`：无有效样本，无法进行能力分析
- `analysis_failed`：分析失败，请检查数据集格式或稍后重试
- `language/reasoning/coding`：分析成功

### 4. 验证结果处理

#### 4.1 验证成功
- 格式验证和能力分析都通过的数据集：
  - `is_verified` 自动设置为 `true`
  - `capability_tag` 更新为具体能力类型
  - 出现在公共数据集列表中
  - 可以用于创建测评任务

#### 4.2 验证失败
- 任一环节失败的数据集：
  - `is_verified` 保持为 `false`
  - `capability_tag` 设置为相应的错误状态
  - 不出现在公共数据集列表中
  - 创建者可以根据错误信息修改后重新上传

### 5. 状态查询与轮询

#### 5.1 状态查询接口
前端可以通过 `GET /api/datasets/{id}/capability_status/` 查询数据集状态：
```json
{
  "code": 200,
  "msg": "查询成功",
  "data": {
    "dataset_id": 1,
    "capability_tag": "processing",
    "capability_dimension": "other",
    "is_processing": true,
    "is_verified": false,
    "has_file": true
  }
}
```

#### 5.2 前端轮询机制
- 上传完成后，前端开始轮询状态接口
- 根据不同状态显示相应的UI提示
- 处理完成后停止轮询

## 状态字段说明

### is_verified（验证状态）
- `false`：数据集未通过测评类型和能力分析测试
- `true`：数据集已通过测评类型和能力分析测试

### capability_tag（能力分析状态）
- `processing`：正在分析能力维度
- `no_file`：文件缺失，无法进行能力分析
- `no_samples`：无有效样本，无法进行能力分析
- `analysis_failed`：分析失败，请检查数据集格式或稍后重试
- `language`：自然语言理解能力
- `reasoning`：数学推理能力
- `coding`：代码能力
- `other`：默认状态，无法分类的数据集

## 验证规则

### 主观测评 (subjective)
- 必需字段：`input`, `reference`
- 字段类型：非空字符串

### 客观测评 (objective)
- 必需字段：`input`, `answer`
- `input` 要求：包含至少两个选项（如 A. B. C.）
- `answer` 要求：单个选项字母（如 A/B/C）

### 对抗测评 (adversarial)
- 必需字段：`input`
- 字段类型：非空字符串

## 前端集成要点

1. **上传后立即轮询**：每2秒查询一次状态
2. **状态UI展示**：根据不同状态显示相应提示
3. **错误处理**：提供清晰的错误信息和处理建议
4. **轮询限制**：最多轮询30次（约1分钟）

## 错误处理机制

### 1. 格式验证错误
- **错误类型**：文件格式错误、字段缺失、数据类型不匹配等
- **处理方式**：直接拒绝上传，返回详细错误信息
- **用户操作**：根据错误提示修改数据集格式后重新上传

### 2. 能力分析错误
- **错误类型**：API调用失败、网络超时、模型响应异常等
- **处理方式**：
  - 自动重试机制（最多3次）
  - 错误信息记录到数据集描述中
  - 设置 `capability_tag="analysis_failed"`
- **用户操作**：检查数据集格式或联系管理员

### 3. 系统错误
- **错误类型**：文件系统错误、数据库错误等
- **处理方式**：记录详细错误日志
- **用户操作**：联系技术支持

## 完整流程图

```
用户上传数据集
       ↓
   格式验证
       ↓
   创建数据集记录
       ↓
   触发异步能力分析
       ↓
   验证结果处理
       ↓
   数据集可用/不可用
```

## 最佳实践建议

### 1. 数据集准备
- 确保数据集格式符合所选测评类型的要求
- 检查数据结构的完整性和一致性
- 提供清晰的数据集描述

### 2. 上传过程
- 选择正确的测评类型
- 确保文件大小不超过限制
- 上传后耐心等待处理完成

### 3. 错误处理
- 仔细阅读错误提示信息
- 根据错误类型采取相应措施
- 必要时联系技术支持

## 注意事项

1. **文件大小限制**：上传文件大小不超过100MB
2. **支持格式**：CSV、JSON、ZIP格式
3. **验证流程**：只有通过格式验证和能力分析的数据集才能公开使用
4. **异步处理**：能力分析在后台异步进行，可能需要一定时间
5. **隐私保护**：未验证通过的数据集只有创建者可见
6. **自动验证**：不再需要人工审核，系统自动根据验证结果设置状态
