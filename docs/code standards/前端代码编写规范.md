前端代码编写规范说明
适用范围：本项目前端部分（Vue 3 + Vite + JavaScript / TypeScript + Axios）。
目标：统一代码风格、降低维护成本、提升可读性与可扩展性，支撑多人协作与课程验收。

一、总体设计原则
1. 单一职责原则（SRP）
•	页面（views）：
o	负责页面结构与交互
o	不直接写复杂业务逻辑
•	组件（components）：
o	负责可复用 UI 单元
o	不直接发起业务级 API 调用
•	API 层（api）：
o	只负责与后端通信
o	不处理 UI 逻辑
•	状态与逻辑（store / composables）：
o	封装跨页面共享状态或通用逻辑

2. 数据流清晰
•	页面 → 调用 API / composable → 更新 state → 驱动视图
•	禁止组件之间相互直接修改彼此的数据



二、项目结构规范
1. 目录结构
src/
 ├─ api/              # 后端接口封装
 │   ├─ user.js
 │   ├─ dataset.js
 │   ├─ task.js
 │   └─ model.js
 ├─ assets/           # 静态资源（图片 / 字体）
 ├─ components/       # 通用组件
 │   ├─ common/
 │   └─ layout/
 ├─ composables/      # 组合式逻辑（hooks）
 │   └─ useAuth.js
 ├─ router/           # 路由
 ├─ store/            # 全局状态（Pinia / Vuex）
 ├─ utils/            # 工具函数
 ├─ views/            # 页面级组件
 ├─ App.vue
 └─ main.js

2. 命名规范
类型	命名规则	示例
文件夹	kebab-case	evaluation-task
Vue 组件	PascalCase	TaskDetail.vue
JS 变量 / 函数	camelCase	fetchTaskList
常量	全大写	MAX_PAGE_SIZE

三、Vue 组件规范
1. 组件拆分原则
•	单个组件 ≤ 300 行
•	组件功能过多 → 拆成子组件

2. 组件结构顺序（强制）
<script setup>
// 1. import

// 2. props / emits

// 3. state / ref

// 4. computed

// 5. methods / functions

// 6. lifecycle
</script>

<template>
  <!-- template -->
</template>

<style scoped>
/* style */
</style>

3. 禁止行为
•	在 template 中写复杂逻辑
•	在组件中直接拼接后端 URL
•	组件之间通过 ref 相互调用



四、API 接口层规范
1. API 统一封装
// api/task.js
import request from '@/utils/request'

export function getTaskDetail(id) {
  return request.get(`/tasks/${id}/`)
}

2. Axios 规范
•	所有请求必须走统一封装
•	统一处理：
o	token 注入
o	401 / 403
o	网络错误

五、状态管理规范
1. 何时使用 store
•	用户登录状态
•	当前用户信息
•	全局配置数据
局部状态 → 组件内部 ref 即可。

2. Store 命名
useUserStore
useTaskStore

六、Composables（hooks）规范
1. 使用场景
•	多组件复用逻辑
•	抽象业务流程（如登录、权限判断）
export function useAuth() {
  const isLogin = ref(false)
  return { isLogin }
}

七、路由规范
1. 路由划分
•	views 下每个文件对应一个路由页面
•	嵌套路由 ≤ 2 层

2. 路由守卫
•	登录校验
•	权限校验
逻辑统一放在 router 层，不写在页面中。

八、样式与 UI 规范
1. 样式原则
•	scoped 为默认
•	避免全局样式污染

2. CSS 命名
•	kebab-case
•	不使用 inline-style

九、异常与提示规范
•	所有 API 错误统一提示
•	禁止 console.log 留在生产代码

十、代码质量与风格
1. 强制要求
•	ESLint / Prettier
•	不允许明显 unused 变量

2. 注释规范
// 获取评测任务列表
function fetchTaskList() {}

十一、禁止事项汇总（必须遵守）
•	 页面直接请求后端 URL
•	 在组件中写大量 if-else 判断业务
•	 中英文混合变量名
•	 一个文件承担多个页面职责

十二、协作与提交规范
•	一个功能一个分支
•	页面级功能独立 commit
feat: add task detail page
fix: handle login redirect
refactor: split task components
