# ZIP数据集审核检测流程说明

## 概述

当用户上传ZIP数据集后，系统会经过一系列自动化审核和检测流程，以确保数据集的质量和适用性。ZIP数据集通常用于包含图片的复杂数据集，其审核流程比JSON和CSV更为复杂，需要同时处理JSON数据文件和图片资源。

## 详细流程

### 1. 数据上传阶段

#### 1.1 文件上传
- 用户通过 `POST /api/datasets/` 接口上传ZIP数据集
- 系统检查文件基本属性：
  - 文件大小不超过100MB
  - 文件格式为支持的类型（CSV、JSON、ZIP）

#### 1.2 ZIP文件结构验证
- **文件格式验证**：检查ZIP文件是否可以正确解压
- **内容检查**：扫描ZIP文件结构，查找JSON数据文件和图片文件
- **文件类型识别**：
  - JSON文件：`.json` 扩展名
  - 图片文件：`.jpg`, `.jpeg`, `.png`, `.gif`, `.bmp`, `.webp`, `.svg`

#### 1.3 数据文件定位
系统按以下优先级查找数据文件：
1. 优先查找 `data.json`
2. 如果不存在，查找第一个JSON文件
3. 如果没有找到JSON文件，返回错误

### 2. 数据解析与验证

#### 2.1 JSON数据提取
- 从ZIP文件中提取JSON数据文件内容
- 解析JSON结构，支持多种数据格式：
  - 直接数组格式：`[{"input": "...", "answer": "..."}, ...]`
  - 对象包含数据数组：`{"data": [...], "total": 100}`
  - 测评类型特定结构：`{"subjective": [...]}`, `{"objective": [...]}`, `{"adversarial": [...]}`

#### 2.2 测评类型特定验证
系统根据用户选择的测评类型（subjective/objective/adversarial）进行特定验证：

**主观测评 (subjective)**：
- 每个条目必须包含 `input` 和 `reference` 字段
- 图像数据集还需要 `image` 字段（图片文件路径）
- `input` 和 `reference` 必须是非空字符串

**客观测评 (objective)**：
- 每个条目必须包含 `input` 和 `answer` 字段
- 图像数据集还需要 `image` 字段（图片文件路径）
- `input` 中必须包含至少两个选项（如 A. B. C.）
- `answer` 必须是单个选项字母（如 A/B/C）

**对抗测评 (adversarial)**：
- 每个条目必须包含 `input` 字段
- 图像数据集还需要 `image` 字段（图片文件路径）
- `input` 必须是非空字符串

#### 2.3 图片文件验证
- **路径验证**：检查JSON中引用的图片路径是否存在于ZIP中
- **格式验证**：确认图片文件为支持的格式
- **数量统计**：统计ZIP中包含的图片数量

### 3. 数据集创建与状态初始化

#### 3.1 数据集记录创建
- 验证通过后，系统创建数据集记录
- 设置初始状态：
  ```python
  is_verified = False  # 未审核
  capability_tag = "processing"  # 正在处理
  capability_dimension = "other"  # 默认能力维度
  ```

#### 3.2 文件信息统计
- 计算文件大小（MB）
- 统计样本数量（从JSON数据中获取）
- 统计图片信息：
  - `has_images`：是否包含图片
  - `image_count`：图片数量

### 4. ZIP数据抽样与转换

#### 4.1 数据抽样
- 系统从ZIP文件中的JSON数据文件里抽取前5条样本
- 保持原始数据结构，用于AI能力分析

#### 4.2 图片路径处理
- 保留原始图片路径信息
- 验证图片文件确实存在于ZIP中
- 记录图片文件大小和格式信息

### 5. 异步能力分析

#### 5.1 触发异步任务
- 数据集创建成功后，系统自动触发 `analyze_dataset_capability` 异步任务
- 该任务使用Celery在后台执行，不阻塞用户操作

#### 5.2 能力维度分析过程
1. **ZIP抽样**：从ZIP文件中抽取前5条样本
2. **AI判断**：调用大模型分析样本，判断数据集的能力维度：
   - `language`：自然语言理解、生成、翻译等
   - `reasoning`：数学推理、逻辑推理等
   - `coding`：代码生成、代码理解等

#### 5.3 能力分析状态更新
分析结果可能的状态：
- `processing`：正在分析中
- `no_file`：文件缺失
- `no_samples`：无有效样本
- `analysis_failed`：分析失败
- `language/reasoning/coding`：分析成功

### 6. 验证结果处理

#### 6.1 验证状态
- 数据集通过格式验证和能力分析后，`is_verified` 自动设置为 `true`
- 验证失败的数据集（`is_verified=false`）不会出现在公共数据集列表中

#### 6.2 验证失败处理
- 格式验证失败：`is_verified` 保持为 `false`，返回详细错误信息
- 能力分析失败：`is_verified` 保持为 `false`，记录错误原因
- 用户可根据错误信息修改数据集后重新上传

#### 6.3 验证成功处理
- 验证通过的数据集（`is_verified=true`）会出现在公共数据集列表中
- 数据集可以用于创建测评任务
- 其他用户可以查看和使用通过验证的数据集

### 7. 图片访问机制

#### 7.1 图片访问接口
系统提供专门的图片访问接口：
- `GET /api/datasets/{id}/image/?filename=xxx.jpg` - 获取单个图片
- `GET /api/datasets/{id}/images/` - 获取图片列表

#### 7.2 图片处理流程
1. 接收图片请求
2. 从ZIP文件中提取指定图片
3. 根据图片扩展名设置正确的Content-Type
4. 返回图片二进制数据

### 8. 状态查询与轮询

#### 8.1 状态查询接口
前端可以通过 `GET /api/datasets/{id}/capability_status/` 查询数据集状态：
```json
{
  "code": 200,
  "msg": "查询成功",
  "data": {
    "dataset_id": 1,
    "capability_tag": "processing",
    "capability_dimension": "other",
    "is_processing": true,
    "is_verified": false,
    "has_file": true,
    "has_images": true,
    "image_count": 10
  }
}
```

#### 8.2 前端轮询机制
- 上传完成后，前端开始轮询状态接口
- 根据不同状态显示相应的UI提示
- 处理完成后停止轮询

## ZIP特有的处理逻辑

### 1. 文件结构解析
系统支持多种ZIP文件结构：

#### 标准结构（推荐）
```
dataset.zip
├── data.json        # 数据文件
├── image1.jpg       # 图片文件
├── image2.png
└── images/          # 可选子目录
    ├── image3.jpg
    └── subdir/
        └── image4.png
```

#### 多JSON文件结构
```
dataset.zip
├── metadata.json     # 元数据
├── data.json        # 优先使用的数据文件
└── images.json      # 备选数据文件
```

### 2. 图片路径处理
- **相对路径**：图片路径必须相对于ZIP根目录
- **路径验证**：系统会验证JSON中引用的图片路径是否存在
- **大小限制**：单个图片文件大小建议不超过10MB

### 3. 数据格式灵活性
ZIP数据集支持更灵活的数据结构：

#### 直接数组格式
```json
[
  {
    "id": 1,
    "input": "请描述这张图片",
    "image": "sample1.jpg",
    "reference": "这是一张风景照片"
  }
]
```

#### 对象包含数据数组
```json
{
  "data": [
    {
      "id": 1,
      "input": "请分类这张图片",
      "image": "images/cat1.jpg",
      "answer": "猫"
    }
  ],
  "total": 100
}
```

#### 测评类型特定结构
```json
{
  "subjective": [
    {
      "id": 1,
      "input": "请分析这张图片",
      "image": "test1.jpg",
      "reference": "图片分析结果"
    }
  ]
}
```

### 4. 错误处理机制

#### ZIP文件错误
- **损坏的ZIP文件**：返回"ZIP文件格式错误"
- **缺少JSON文件**：返回"ZIP文件中未找到JSON文件"
- **JSON格式错误**：返回"JSON文件格式错误，无法解析"

#### 图片相关错误
- **图片路径不存在**：在审核时给出警告，但不阻止上传
- **不支持的图片格式**：忽略不支持的图片文件
- **图片文件过大**：记录警告，但不阻止上传

## 完整流程图

```
用户上传ZIP文件
       ↓
   ZIP文件结构验证
       ↓
   查找JSON数据文件
       ↓
   提取并解析JSON数据
       ↓
   测评类型特定验证
       ↓
   图片文件验证与统计
       ↓
   创建数据集记录
       ↓
   触发异步能力分析
       ↓
   等待管理员审核
       ↓
   审核通过
       ↓
   数据集可用（支持图片访问）
```

## 最佳实践建议

### 1. ZIP文件准备
- 使用标准ZIP格式，避免使用其他压缩格式
- 确保ZIP文件没有密码保护
- 使用相对路径引用图片，不要使用绝对路径
- 优先使用 `data.json` 作为数据文件名

### 2. 图片文件管理
- 使用常见的图片格式（JPEG、PNG）
- 控制单个图片文件大小，建议不超过10MB
- 使用有意义的图片文件名，避免特殊字符
- 将图片组织在合理的目录结构中

### 3. JSON数据结构
- 根据测评类型包含必要的字段
- 确保图片路径与实际文件匹配
- 添加ID字段便于追踪和管理
- 保持数据结构的一致性

### 4. 上传过程
- 选择正确的测评类型
- 确保文件大小不超过100MB
- 上传后耐心等待处理完成
- 检查图片是否能正常访问

### 5. 错误处理
- 仔细阅读错误提示信息
- 根据错误类型采取相应措施
- 必要时联系技术支持

## 注意事项

1. **文件大小限制**：上传文件大小不超过100MB
2. **支持格式**：ZIP格式，内含JSON和图片文件
3. **审核流程**：只有管理员审核通过的数据集才能公开使用
4. **异步处理**：能力分析在后台异步进行，可能需要一定时间
5. **隐私保护**：未审核通过的数据集只有创建者和管理员可见
6. **图片访问**：通过专门的API接口访问ZIP中的图片文件
7. **路径要求**：图片路径必须使用相对于ZIP根目录的相对路径
